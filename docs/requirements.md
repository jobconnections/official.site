# **コーポレート・求人サイト 構築仕様・構成書**

## **1\. プロジェクト概要**

本プロジェクトは、既存のコーポレートサイト（https://www.jobconnections.jp/）のデザインおよびコンテンツを流用し、新たに求人管理機能と多言語表示機能を実装したWebサイトとして再構築するものである。

最大の目的は、運用コストの極小化（ドメイン代以外の完全無料化）と、サーバー保守作業を一切発生させない運用体制の確立である。

## **2\. システム構成と採用技術**

本システムは、専用サーバーやデータベースを持たない「静的ホスティング ＋ GitベースCMS」の構成を採用する。

| 区分 | 採用技術・サービス | 費用 | 選定理由・役割 |
| ----- | ----- | ----- | ----- |
| **ホスティング / デプロイ** | Netlify | 無料（Free Tier） | 静的ファイルの高速配信およびGitHubと連動した自動デプロイを行う。 |
| **静的サイトジェネレーター (SSG)** | Astro | 無料（オープンソース） | MarkdownおよびYAML Frontmatterを読み込み、多言語対応の静的HTMLページ（求人一覧・詳細・JSON-LD含む）を自動生成する。多言語ルーティング（i18n）と静的ビルドを標準サポートし、Netlifyへのデプロイは公式アダプターで完結する。 |
| **コンテンツ管理 (CMS)** | Sveltia CMS | 無料（オープンソース） | データベースを使わずに、ブラウザから日本語・英語・ポルトガル語等の求人情報を投稿・更新するための管理画面を提供する。 |
| **CMS認証** | Netlify Identity | 無料（最大1,000ユーザー） | Sveltia CMSの管理画面ログイン認証を担う。設定が容易でサーバーレスに完結するため採用する。 |
| **データ保管 (データベース代替)** | GitHub | 無料 | 投稿された多言語求人データ（テキスト・画像）を安全に保管・バージョン管理する。 |
| **応募フォーム** | Netlify Forms | 無料（月100件まで） | サーバーレスで各言語からの応募者の情報および添付ファイル（履歴書等）を受信する。 |

## **3\. 運用前提・制約条件**

本システムは、以下の運用環境・規模を前提として設計される。

* **掲載求人数:** 50件以下（静的ビルドおよびサイトパフォーマンスが最適に保たれる規模）。
* **編集担当者数:** 1〜2名（編集内容の競合リスクが発生しない体制）。
* **画像アセット:** 求人1件につき画像0〜1枚程度。アップロード可能な形式はJPEGまたはWebPとし、1枚あたり2MB以下を推奨する。Sveltia CMS の `config.yml` に `transformations` ブロックを設定することで、アップロード時にブラウザ側（クライアントサイド）でWebP形式への変換・品質圧縮・最大解像度へのリサイズを自動的に行い、変換済みファイルをGitHubへコミットする。
* **サイト反映時間:** 管理画面での投稿後、自動ビルド処理により数分でサイトへ反映される仕組みを許容する。
* **ランニングコスト:** 月額0円（年間ドメイン更新料1,000〜3,000円程度のみ発生）。
* **GitHubリポジトリの管理:** リポジトリはクライアント所有のGitHubアカウントで管理する。制作会社はコラボレーターとして開発期間中のみアクセス権を付与される。

## **4\. 多言語化仕様**

本サイトはグローバル対応および外国人採用を考慮し、多言語対応を備える。

### **4.1 初期対応言語**

1. **日本語（Japanese / ja）** \- デフォルト言語
2. **英語（English / en）**
3. **ポルトガル語（ブラジル） (Portuguese \- Brazil / pt-br)**

### **4.2 将来の言語拡張性**

管理画面設定およびビルド処理において、言語コード（例: ベトナム語、中国語等）を追加定義するだけで、システム構造を大規模改修することなく新しい言語を容易に追加・拡張できる設計とする。

### **4.3 URL構造とルーティング**

検索エンジン最適化（SEO）および言語識別のため、言語ごとにURLパスを分離する。

* 日本語トップ / 求人一覧: `/` および `/jobs/`
* 英語トップ / 求人一覧: `/en/` および `/en/jobs/`
* ポルトガル語トップ / 求人一覧: `/pt-br/` および `/pt-br/jobs/`
* 応募フォーム: `/apply/`、`/en/apply/`、`/pt-br/apply/`
* 応募完了（サンクス）: `/thanks/`、`/en/thanks/`、`/pt-br/thanks/`
* プライバシーポリシー: `/privacy/`、`/en/privacy/`、`/pt-br/privacy/`

#### **求人詳細ページのURLスラッグ（ID）命名規則**

求人データのディレクトリ名およびURL上のスラッグは、以下の規則で統一する。

* **形式:** `JOB` ＋ 登録日時（`YYYYMMDDHHmmss`、ゼロパディング必須）
* **例:** `JOB20260805020543` → URL: `/jobs/JOB20260805020543/`
* CMS上で新規求人を作成する際、Sveltia CMS の Slug 自動生成機能を使用して上記形式を自動付与する。

#### **hreflang タグの実装方針（多言語SEO）**

各ページの `<head>` 内に `hreflang` タグを Astro ビルド時に自動出力する。Google に対して言語・地域バリアントを正しく伝達し、多言語ページの重複コンテンツ判定を回避する。

```html
<!-- 出力イメージ（求人詳細ページの場合） -->
<link rel="alternate" hreflang="ja"        href="https://www.jobconnections.jp/jobs/JOB20260805020543/" />
<link rel="alternate" hreflang="en"        href="https://www.jobconnections.jp/en/jobs/JOB20260805020543/" />
<link rel="alternate" hreflang="pt-BR"     href="https://www.jobconnections.jp/pt-br/jobs/JOB20260805020543/" />
<link rel="alternate" hreflang="x-default" href="https://www.jobconnections.jp/jobs/JOB20260805020543/" />
```

* 特定言語版が存在しない求人（フォールバック対象）は、その言語の `hreflang` タグを出力しない。

### **4.4 画面UIとナビゲーション**

ヘッダー領域に言語切替用ナビゲーション（日本語 / English / Português）を常時配置し、選択された言語のコンテンツを表示する。

## **5\. 機能仕様**

### **5.1 フロントエンド（閲覧者向け画面）**

* **既存コンテンツの移植:** 現在のサイトデザイン・会社概要等のコンテンツをそのまま引き継ぐ（主要要素は多言語化対応）。
* **求人一覧ページ:** 募集中の求人案件を言語別に**カード型レイアウト**で一覧表示し、詳細へ誘導する。表示順は**最終更新日の新しい順**とする。
* **求人一覧フィルタリング:** JavaScriptによるクライアントサイドフィルタリングで実装する。以下の条件で絞り込みができる。
  * 勤務地（市区町村・都道府県）
  * 給与種別（時給 / 日給 / 月給）
  * 給与下限・給与上限（数値で絞り込み。給与種別を選択後に有効化）
  * 日本語能力（不問 / N4以上 / N3以上 / N2以上 / N1以上）
* **求人詳細ページ:** 各求人の募集条件・業務内容を該当言語で表示する。ページ内には以下の複数の連絡手段を提供するボタンを設ける。
  * **「応募する」ボタン:** 言語別の応募フォームページ（`/apply/`、`/en/apply/`、`/pt-br/apply/`）へ遷移する。
  * **WhatsApp で連絡するボタン:** `https://wa.me/` の国際番号形式URLを使用し、WhatsApp チャットを直接開く。
  * **LINE で連絡するボタン:** LINE 公式アカウントへのリンク（`https://line.me/` 形式のURL）を設定する。
  * **メールで連絡するボタン:** `mailto:` リンクを使用し、メールクライアントを起動して採用担当者へ直接メールを送れるようにする。
  > **【実装後設定】** 上記 WhatsApp・LINE・メール各ボタンに設定する電話番号・LINE アカウントURL・メールアドレスは、実装完了後に担当者が確定値を確認のうえ、サイト設定ファイル（`astro.config.mjs` または専用の定数ファイル）へ記載する。実装フェーズでは仮のプレースホルダー値を使用してビルドが通ることを確認する。
* **検索エンジン連携:** Google お仕事検索（Google Job Search）の表示に対応するため、求人詳細ページ内に専用の構造化データ（JSON-LD）を自動出力する。構造化データ内には該当ページの言語指定（`inLanguage` 属性）を正しく含める。
* **OGP（Open Graph Protocol）多言語対応:** 各ページの `<head>` 内に言語ごとの OGP タグを出力する。`og:locale` は表示言語に応じて切り替え（日本語: `ja_JP` / 英語: `en_US` / ポルトガル語: `pt_BR`）。求人詳細ページの `og:image` は当該求人のメイン画像を使用し、未設定の場合はサイト共通のデフォルト画像を使用する。

#### **多言語化対象ページと翻訳原稿方針**

| ページ | 日本語 | 英語 | ポルトガル語 | 翻訳原稿の調達 |
| ----- | :---: | :---: | :---: | ----- |
| トップページ | ✅ | ✅ | ✅ | 日本語の求人を作成する際に合わせて英語・ポルトガル語原稿をアップロードする |
| 求人一覧ページ（`/jobs/`） | ✅ | ✅ | ✅ | CMSデータから自動生成（翻訳原稿は各求人のCMS入力時に担当者が用意） |
| 求人詳細ページ（`/jobs/[id]/`） | ✅ | ✅ | ✅ | CMSデータから自動生成（同上） |
| 応募フォームページ（`/apply/`） | ✅ | ✅ | ✅ | UIラベルのみ多言語化（開発時に実装） |
| 応募完了（サンクス）ページ（`/thanks/`） | ✅ | ✅ | ✅ | 開発時に実装 |
| プライバシーポリシー（`/privacy/`） | ✅ | ✅ | ✅ | 日本語の求人を作成する際に合わせて原稿をアップロードする |

**フォールバック方針:** 特定言語の本文が未入力の求人は、その言語版の詳細ページを非公開とし、求人一覧にも表示しない。

### **5.2 求人管理機能（管理者向け画面）**

* **アクセス指定:** サイト内の特定アドレス（`/admin`）からログイン画面へ接続する。
* **認証方式:** Netlify Identity を使用する。管理画面URLは `/admin/` とし、Netlify Identity のウィジェットを埋め込む。
* **データ保存形式:** CMS経由で作成された求人データは、Markdown + YAML Frontmatter 形式で GitHub リポジトリの `content/jobs/[job-id]/` ディレクトリ配下に言語別ファイル（`ja.md` / `en.md` / `pt-br.md`）として保存する。
* **入力管理項目:** 1つの求人登録画面において、以下の項目を言語別（日本語・英語・ブラジルポルトガル語）に入力可能とする。
  * 職種タイトル
  * 公開ステータス（公開 / 下書き）
  * 雇用形態（正社員 / 契約社員 / アルバイト / 業務委託）
  * 勤務地（市区町村・都道府県を個別入力）
  * 給与種別（時給 / 日給 / 月給 をセレクトボックスで選択）
  * 給与下限・給与上限（数値で入力）
  * 日本語能力要件（不問 / N4以上 / N3以上 / N2以上 / N1以上をセレクトボックスで選択）
  * メイン画像（任意設定）
  * 募集要項・詳細本文（テキスト装飾対応）

#### **Google Job Search（Google お仕事検索）対応フィールド**

JSON-LD 構造化データの自動出力に必要な以下のフィールドをCMS入力項目に含める。サイト共通項目（会社名・国コード・通貨）はビルド時に設定ファイルから自動挿入し、CMS入力の手間を省く。

| フィールド名 | 必須 / 推奨 | JSON-LDプロパティ | 入力方法 |
| ----- | ----- | ----- | ----- |
| 掲載開始日 | **必須** | `datePosted` | CMS投稿日を自動設定 |
| 掲載有効期限 | 推奨 | `validThrough` | CMS画面から任意入力 |
| 会社名 | **必須** | `hiringOrganization.name` | 固定値（自動出力） |
| 会社サイトURL | **必須** | `hiringOrganization.sameAs` | 固定値（自動出力） |
| 勤務地（市区町村） | **必須** | `jobLocation.address.addressLocality` | CMS入力 |
| 勤務地（都道府県） | **必須** | `jobLocation.address.addressRegion` | CMS入力 |
| 勤務地（国コード） | **必須** | `jobLocation.address.addressCountry` | 固定値 "JP"（自動出力） |
| 給与種別 | 推奨 | `baseSalary.unitText` | セレクトボックスで入力 |
| 給与下限 | 推奨 | `baseSalary.minValue` | 数値で入力 |
| 給与上限 | 推奨 | `baseSalary.maxValue` | 数値で入力 |
| 給与通貨 | 推奨 | `baseSalary.currency` | 固定値 "JPY"（自動出力） |

### **5.3 応募フォーム機能**

* **多言語対応:** 表示言語に応じたフォーム項目名および案内テキスト（日本語 / 英語 / ポルトガル語）を表示する。
* **入力項目:** お名前、メールアドレス、電話番号、志望動機・メッセージ。
* **ファイル添付:** 履歴書および職務経歴書（PDF、Word形式等）の添付を必須とする。ファイルサイズの上限は Netlify Forms Free Tier の制約に準拠し、1回の送信あたり最大 **10MB** とする。
* **スパム対策:** 不正な自動投稿を防ぐ仕組み（ハニーポット機能）を備える。
* **通知機能:** 応募受付時、Netlify Forms の Notification Emails 機能を使用して、指定の採用担当者メールアドレス宛へ自動通知を送信する。通知先メールアドレスは Netlify 管理画面で設定する。
* **送信完了後の画面遷移:** 送信完了後、言語別の専用サンクスページへリダイレクトする（`/thanks/`、`/en/thanks/`、`/pt-br/thanks/`）。サンクスページには応募受付の旨および「通常3営業日以内に返信する旨」を各言語で表示する。
* **応募者への自動返信メール:** Netlify Forms 無料プランの制約により自動返信メールは実装しない。代替として、サンクスページにてその旨を明示する。

## **6\. サイトの構造方針**

Webサイトの構成要素は、以下の方針で整理・配置する。

* **トップページ:** 既存サイトのトップ画面を配置（言語別ルーティング対応）。
* **求人エリア:** 求人一覧および各求人の詳細ページを言語別に出力する専用領域を設ける。
* **データ格納領域:** CMS経由で作成された多言語求人データを保管する領域を設ける。
* **管理画面領域:** Sveltia CMSのプログラムと設定ファイルを配置する領域を設ける。

### **Astro プロジェクト構造（ディレクトリ設計）**

```
/
├── public/
│   └── admin/                   ← Sveltia CMS 管理画面（index.html + config.yml）
├── content/
│   └── jobs/
│       └── [job-id]/
│           ├── ja.md            ← 日本語求人データ
│           ├── en.md            ← 英語求人データ
│           └── pt-br.md         ← ポルトガル語求人データ
├── src/
│   ├── pages/
│   │   ├── index.astro          ← 日本語トップ
│   │   ├── jobs/[...slug].astro ← 日本語求人一覧・詳細
│   │   ├── apply/index.astro    ← 日本語応募フォームページ
│   │   ├── thanks/index.astro   ← 日本語サンクスページ
│   │   ├── en/                  ← 英語ページ群
│   │   └── pt-br/               ← ポルトガル語ページ群
│   ├── layouts/
│   └── components/
├── _redirects                   ← Netlify リダイレクト設定
└── astro.config.mjs
```

## **7\. 他構成との比較および選定理由**

* **microCMS等の有料/有料枠ありヘッドレスCMSを採用しない理由:** データ件数の制限やリクエスト上限を気にすることなく、完全無料での維持を担保するため。
* **外部フォームサービス（Formspree等）を採用しない理由:** 無料プランでは求人応募に必要な「履歴書等のファイル添付」に対応していないため。
* **レンタルサーバー・WordPressを採用しない理由:** 月額の固定費を排除し、セキュリティ対策やサーバーのメンテナンス工数をゼロにするため。
* **11ty (Eleventy) ではなく Astro を採用する理由:** Astro は多言語ルーティング（i18n）とMarkdownのビルトインサポートを標準装備しており、少人数運用における設定・保守コストを最小化できるため。

## **8\. ドメイン移行・デプロイフロー・リダイレクト計画**

### **8.1 DNS切り替えとSSL証明書**

* 既存ドメイン `jobconnections.jp` のDNSレコードを、Netlify が提供する CNAME / A レコード値に変更する。
* SSL証明書は Netlify が Let's Encrypt を利用して自動発行・自動更新を行うため、手動の証明書管理は不要。

### **8.2 リダイレクト設定**

リダイレクトはリポジトリルートに配置する `_redirects` ファイルで管理する。リニューアルに伴いURLが変更される箇所は、SEO維持のため 301 リダイレクトを設定する。

| 変更前URL（既存） | 変更後URL | ステータス | 備考 |
| ----- | ----- | ----- | ----- |
| `/privacy.html` | `/privacy/` | 301 | プライバシーポリシーページの拡張子なし移行 |
| `/jobs` | `/jobs/` | 301 | 末尾スラッシュ統一 |
| その他変更が生じたURL | 各新URL | 301 | 実装確定後にリスト化し `_redirects` へ追記 |

### **8.3 自動デプロイフロー**

1. 編集者が Sveltia CMS（`/admin/`）から求人を投稿・更新する。
2. Sveltia CMS が GitHub リポジトリの `content/jobs/` ディレクトリへコミットを自動作成する。
3. GitHub へのコミットを Netlify が検知し、Astro の自動ビルドを開始する。
4. ビルド完了後（目安：1〜3分）、全言語の静的ファイルが本番公開される。

### **8.4 サイトマップ（sitemap.xml）の自動生成**

Astro の `@astrojs/sitemap` インテグレーションを使用し、ビルド時に全言語・全ページを含む `sitemap.xml` を自動生成する。求人の追加・更新・削除のたびに最新の状態で再生成されるため、手動メンテナンスは不要。生成された `sitemap.xml` は `https://www.jobconnections.jp/sitemap.xml` として公開し、Google Search Console に登録する。
